01概要

項目仕様
種類ブラウザ上で動くステレオ 2 ミックス用マスタリングエンジン（信号処理はすべて自作。外部ライブラリは MP3 エンコードの lamejs のみ）
内部処理44.1 kHz、64 bit 浮動小数点（ブロック処理）
入力ブラウザがデコードできる形式（WAV / MP3 / FLAC / M4A / AAC / OGG / Opus / AIFF）。読み込み時に 44.1 kHz へ変換
出力WAV 16 bit（TPDF ディザ）/ WAV 24 bit / MP3 320 kbps、44.1 kHz または 48 kHz
ラウドネス測定ITU-R BS.1770-4 / EBU R128（Integrated・Short-term・Momentary・LRA）、True Peak は 4 倍オーバーサンプリング
既定の目標-10.8 LUFS / -1.0 dBTP
設計の元AIDAW のステム別マスタリングチェーンを 2 ミックス用に移植。一般的な楽曲の測定値を目安にした自動設定

02システム構成

メインスレッド (app.js)        UI・デコード・書き出しファイル生成（WAV / MP3）
   │ postMessage
   ├─ Web Worker (worker.js)     解析 → 自動設定 → 校正 → ラウドネス解決 → オフライン書き出し
   │                              engine/session.js（Node 用ハーネス tools/ と共通）
   └─ AudioWorklet (worklet.js)  リアルタイム再生：同じ MasterChain ＋ LiveMeter

リアルタイム再生と書き出しは同じ MasterChain を使うので、試聴した音と書き出した音は一致します（書き出しでは最終の音量・ピーク補正のみ追加）。

03信号処理チェーン

入力トリム（-14 LUFS 基準にそろえる）
 → HPF（4 次 Butterworth）
 → トーン EQ（低域シェルフ 90 Hz / 低域ベル / こもり / 高域シェルフ / エア 16 kHz）
 → 手動 EQ 4 バンド
 → ダイナミック EQ（最大 10 バンド、大きい瞬間だけ働く）
 → パンチ（150 Hz 以下のトランジェント）
 → グルーコンプ
 → カラー（テープ／真空管系の倍音）
 → 空間（FDN リバーブ、数 % のみ）
 → ステレオ（低域モノラル化・幅・M/S プレゼンス）
 → True Peak リミッター（ラウドネス固定でドライブを自動決定）

各モジュールはスイッチで素通しにできます（素通し時は中立値で処理）。

ダイナミック EQ（ダイナミックベル）

  • 構造：y = x + (g − 1)·BP(x)。中心ゲイン 0 dB のバンドパスを使うので、係数を再計算せずにサンプルごとにゲインを動かせる正確なベルになります。
  • 検出：バンド信号の L/R 連動ミッド、パワーエンベロープ。
  • 自動校正：スレッショルドは曲ごとに解析で決めます。曲の中で大きい上位 15 % の瞬間に、指定した深さ（dB）だけ効くように合わせます。EQ で同じ帯域を持ち上げている分は深さに足すので、大きい瞬間の正味のカット量が指定値になります。
  • 主なバンド（自動）：8 kHz 刺さり抑え（Q 0.5）、2〜5 kHz の鳴り続ける共振（Q 8）、大きい場面で伸びる高域の刺さり（Q 3）、9.5 kHz シャリシャリ抑え（Q 2）、7 kHz 歯擦音（Q 2、速いアタック）。

パンチ

150 Hz の相補分割（low = LP2(x)、high = x − low なので合計は常に入力と一致）。低域側だけで速い／遅いエンベロープの差からアタックと余韻を整形するので、スネアやシンバルは硬くなりません。整形による低域の音量変化は、オフラインで測ったメイクアップで打ち消します。

グルーコンプ

フィードフォワード、ステレオ連動。サイドチェーンは 100 Hz でハイパス。RMS（本体）とピークの二重検出、ソフトニー 6 dB、プログラム依存リリース。自動設定は 1.25:1（密な音源は 1.1:1）、アタック 30 ms、リリースは曲の BPM に同期します（16 分音符 / 8 分音符）。

カラー

2 倍オーバーサンプリングの非対称 tanh サチュレーション（偶数次＋奇数次の倍音）。小信号ゲインを 1 に正規化してあるので、ドライブを上げても音量ではなく音色だけが変わります。

空間

8 ラインのフィードバックディレイネットワーク（アダマール行列、ループ内ダンピング、プリディレイ最大 250 ms）。ウェット信号を数 % だけ加えます。自動設定のプリディレイは 16 分音符の長さです。

ステレオ

M/S 処理。サイドを 4 次でハイパスして指定周波数以下をモノラル化します。サイドゲインでステレオ幅を調整します。プレゼンスはミッドの 3 kHz ベルを上げ、同じ帯域のサイドを半分だけ下げて、ボーカルを前に出します。

True Peak リミッター

  • ルックアヘッド 2 ms。4 倍ポリフェーズ補間で、サンプル間ピークを含めた真のピークを検出します。
  • 必要ゲイン → ルックアヘッド窓の最小値ホールド → リリース平滑化（長く続く圧縮には 6 倍遅いリリースを併用）→ 同じ長さの箱型フィルタ。窓の中のゲインはすべてピーク地点の必要ゲイン以下になるので、出力がシーリングを超えません。

06自動設定（処方）

診断から全パラメータを決め、各項目に理由の文章を付けます。「すでにマスタリング済みか」は判定しません。質の低いマスターが付いた音源もあるので、どの音源も同じ測定基準に合わせます。

判定条件主な変化
808ベース p10 < 45 Hz かつ p50 < 50 Hz-10.0 LUFS、HPF 25 Hz、低域シェルフなし
バラードクレスト ≥ 15 dB かつセクション差 ≥ 6 dB-13 LUFS、半分のテンポでリリース、共振カットは浅め、8k・シャリシャリ処理なし
密な音源クレスト < 12.5 dBキック・倍音・空間・低域の足し算を控えめに
ドラムが少ない低域オンセット < 0.6 / 秒パンチ控えめ、低域ベルなし
明るい音源低域／高域比 < 10 dB8k は -1 dB のみ、歯擦音処理オフ
とても暗い音源低域／高域比 ≥ 15 dB高域の持ち上げは最大 +1 dB

高域の合わせ込み（一般的な楽曲の目安）

  1. 5 kHz 以上：4.3 kHz のなだらかな高域シェルフを二分探索で決め、大きい場面の 5 kHz 以上の比率を一般的な楽曲の中央値 -16.9 dB に合わせます（持ち上げは最大 +4 dB）。
  2. 9〜10 kHz：ラウドネスを固定した状態でマスターを実際にレンダリングし、大きい場面の 8.5〜10.5 kHz を 2 つの値で測ります（8.5 kHz ハイパスと 10.5 kHz ローパスの 2 段フィルター、2 ms 単位）。
    • 量（帯域の比率）：一般的な楽曲の上限 -26.6 dB を 0.5 dB 以上超えたら、超えた分（最大 3 dB）だけシャリシャリ抑え（9.5 kHz）を深くし、高域シェルフは超過分の 0.3 倍だけ下げます（暗くしすぎないよう、主役はシャリシャリ抑え）。
    • 瞬間的な突き出し（2 ms ごとの最大と中央値の差）：一般的な楽曲の上限 11.1 dB を超えたら、シャリシャリ抑えを 3 dB にします。シェルフは触りません。
    そのあと、もう一度ラウドネスを解きます。バラードととても暗い音源は対象外です。
  3. 共振：一般的な楽曲では周囲より +3〜4 dB に収まっているので、+3.5 dB 以上突き出たピークを狭く（Q 8）、大きい瞬間だけカットします。1/12 オクターブ以内のピークは、1 つのカットにまとめます。大きい瞬間だけのカットは曲全体では半分ほどしか効かないため、深さは超過分の 2 倍（最大 6 dB）。バラードは浅め（最大 1.5 dB）。

07ラウドネス制御

  • リミッター手前までの処理結果をキャッシュし、リミッターのドライブだけを割線法で解いて、目標 Integrated LUFS に合わせます（許容誤差 0.05 LU）。
  • 高速化のため、先に曲中の 8 か所の 4 秒抜粋（1.5 秒の助走付き）で解き、全曲との差を記録します。以後の編集中は抜粋だけで解き直します（約 5 倍速）。
  • 書き出し時は全曲で測り直して、目標から 0.1 LU 以上ずれていればドライブを補正します。

08ジャンルと好み

  • ジャンル：自動設定の上に重ねる層です。各ジャンルは目標（LUFS、低域／高域比、幅）と固定の性格付けを持ちます。音色と幅の動かし方は曲の診断値から決めます（例：低域／高域比の差 × 0.45 を低域シェルフに、× −0.35 を高域シェルフに、それぞれ ±3 / ±2.5 dB まで）。
  • 好み（スパイス）：8 つの方向軸（±3 段）と 3 つの補正（0〜3 段）。1 段ごとに複数のスライダーを診断に応じた量だけ動かします。適用量は記録されるので、正確に元に戻せます。
  • 好みの学習：書き出しのたびに、自動設定と最終設定の差を学習率 0.35 の移動平均で覚え、次の曲の自動設定に加えます。

09書き出しと品質確認

  1. 曲全体をオフラインで処理します（リアルタイム再生と同じチェーン、レイテンシ補正済み）。
  2. Integrated LUFS を測り、目標とのずれを補正します（最大 2 回）。
  3. True Peak がシーリングを超えていれば、シーリングを下げて再処理します（最大 5 回）。
  4. 48 kHz 書き出しはリサンプル後に True Peak を再確認し、超えた分だけ全体を下げます。
  5. 16 bit は 1 LSB の TPDF ディザを加えて量子化します。MP3 は lamejs で 320 kbps にエンコードします。
  6. 最終的な kHz / LUFS / dBTP を画面に表示します。

10動作環境

  • AudioWorklet・Web Worker（module）・Web Audio API に対応したブラウザ（Chrome / Edge / Safari / Firefox の最新版）。
  • 処理はすべてローカルで行い、音声データを外部に送信しません。
  • 設定・プリセット・学習データ・言語の選択は、ブラウザの localStorage に保存します。
  • 外部から読み込むもの：lamejs（MP3 エンコーダ, jsDelivr）、Google Fonts。
AETHERMASTER 5 · TECHNICAL SPECIFICATION

Technical Specification

As of engine 2026-09-28.4. Figures are defaults or auto-prescription values.

01Overview

  • What it is: a stereo mastering engine that runs in the browser. The DSP is written from scratch; the only library is lamejs, for MP3 encoding.
  • Processing: 44.1 kHz, 64-bit float, block processing.
  • Input: any format the browser can decode. It is converted to 44.1 kHz on load.
  • Output:
    • WAV 16-bit (TPDF dither), WAV 24-bit or MP3 320 kbps;
    • 44.1 or 48 kHz.
  • Metering:
    • ITU-R BS.1770-4 / EBU R128: integrated, short-term and momentary loudness, and LRA;
    • true peak with 4× oversampling.
  • Default target: -10.8 LUFS / -1.0 dBTP.
  • Origin: a 2-mix port of the AIDAW stem-mastering chain, with automatic settings guided by measurements of typical masters.

02Architecture

Main thread (app.js)          UI, decoding, WAV/MP3 file encoding
   ├─ Web Worker (worker.js)   analysis → prescription → calibration → loudness solve → offline render
   └─ AudioWorklet             realtime playback: the same MasterChain + LiveMeter

03Signal chain

input trim (to -14 LUFS) → HPF (4th-order Butterworth) → tone EQ → manual EQ ×4
 → dynamic EQ (up to 10 bands, loud moments only) → punch (<150 Hz transients)
 → glue compressor → colour (saturation) → space (FDN) → stereo (mono lows, width, M/S presence)
 → true-peak limiter (drive solved by the loudness lock)

04Modules

  • Tone EQ (RBJ biquads):
    • 90 Hz low shelf, ±6 dB;
    • low bell, 40–120 Hz, Q 1.2;
    • mud bell, 150–500 Hz, Q 1.0;
    • broad high shelf, 2–10 kHz, Q 0.45, -8 to +3 dB;
    • 16 kHz air shelf;
    • 4 manual peaking bands (±12 dB, Q 0.3–10).
  • Dynamic bells:
    • They compute y = x + (g−1)·BP(x) with a 0 dB bandpass, which gives an exact bell whose gain can change every sample.
    • Thresholds are calibrated per song, so the loudest 15 % of the song gets the set depth.
    • Static EQ boosts at the same frequency are added to the depth.
  • Punch: a complementary split at 150 Hz, with transient shaping on the low band only and a measured makeup.
  • Glue: a feed-forward, linked compressor.
    • The sidechain is high-passed at 100 Hz.
    • Detection is dual (RMS and peak), with a 6 dB soft knee.
    • Auto settings are 1.25:1 with releases synced to the BPM.
  • Colour: asymmetric tanh at 2× oversampling, normalised to unity small-signal gain.
  • Space: an 8-line FDN (Hadamard mixing, damped loop, pre-delay up to 250 ms), used at a few percent wet.
  • Stereo:
    • The side is high-passed (4th order) to make the lows mono.
    • Width is the side gain.
    • Presence adds a mid bell at 3 kHz and cuts the side there by half as much.
  • Limiter:
    • 2 ms lookahead, with true-peak detection by 4× polyphase interpolation.
    • The required gain goes through a sliding-window minimum, release smoothing (plus a 6× slower second release) and a box filter of the same length, so the output never exceeds the ceiling.

05Analysis

  • Loudness: integrated LUFS, LRA, 10 s section loudness and crest factor.
  • Tone: low/high ratio (20–250 Hz vs 4–16 kHz) and the long-term spectrum.
  • Loud parts: bands that grow in the loudest 15 % of frames.
  • Resonances: persistent 2–5 kHz peaks.
  • Treble: the share above 5 kHz and at 9–10 kHz in loud parts.
  • Rhythm: BPM, folded into 70–180, and low-band onset rate.
  • Bass: the f0 distribution, used to detect 808s.
  • Stereo: side energy in the lows and highs.

06Auto prescription

  • Every source is taken to the same measured targets. There is no "already mastered" verdict.
  • Special cases:
    • 808 → -10 LUFS, HPF 25 Hz;
    • ballad (crest ≥ 15 dB, section spread ≥ 6 dB) → -13 LUFS, half-tempo releases;
    • dense source (crest < 12.5 dB) → lighter additive moves;
    • bright source → lighter high control;
    • very dark source → treble lift of +1 dB at most.
  • Treble above 5 kHz: the 4.3 kHz shelf is solved so the loud-part share above 5 kHz hits the typical median of -16.9 dB.
  • 9–10 kHz:
    • The loudness-locked master is rendered and its loud parts are measured through an 8.5 kHz high-pass and 10.5 kHz low-pass (two stages each), in 2 ms chunks.
    • Amount (band share): if it is more than 0.5 dB above the upper end of typical masters (-26.6 dB), the 9.5 kHz bell is deepened by the excess (at most 3 dB) and the shelf is lowered by only 0.3 × the excess, so the bell does the work and the song does not get dull.
    • Spikes (loudest 2 ms chunk vs. the median): if they exceed the typical upper end of 11.1 dB, the 9.5 kHz bell is set to 3 dB and the shelf is left alone.
    • The loudness is then solved again.
  • Resonances: typical masters keep them within +3–4 dB of their neighbourhood, so peaks ≥ +3.5 dB are cut narrowly (Q 8) on loud moments only; peaks within 1/12 octave of each other share one cut. Loud-only cuts act at about half strength over the whole song, so the depth is 2× the excess (max 6 dB); shallower for ballads (max 1.5 dB).

07Loudness lock

  • The pre-limiter render is cached, and the limiter drive is solved by the secant method to the target (±0.05 LU).
  • Edits are re-solved on eight 4 s excerpts plus the measured excerpt/full offset, which is about 5× faster.
  • The export re-measures the whole song.

08Genres, taste and learning

  • Genres are a layer on top of the auto settings. Their tone and width moves are sized from the diagnosis.
  • Taste: 8 axes (±3 steps) and 3 fixes (0–3). The applied deltas are recorded, so undo is exact.
  • Learning: an exponential average (rate 0.35) of your final-minus-auto offsets, applied to the next song.

09Export and QC

  1. An offline render of the whole song, latency-compensated.
  2. A LUFS correction, up to 2 passes.
  3. A true-peak correction, up to 5 passes.
  4. At 48 kHz, resampling followed by a peak re-check.
  5. A 1 LSB TPDF dither for 16-bit, or lamejs at 320 kbps for MP3.
  6. The measured kHz / LUFS / dBTP are shown.

10Requirements

  • A browser with AudioWorklet, module Web Workers and the Web Audio API.
  • All processing is local, and no audio is sent anywhere.
  • Settings, presets, learning and the language choice are stored in localStorage.
  • External loads: lamejs (jsDelivr) and Google Fonts.
